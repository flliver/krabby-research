### Deployment contract (as evaluated)

- **Switch:** HARD switch, no blending, no debounce: the stand net acts on stand holds, the walker (S1) on every other row; both networks run every step (sn_common.route_actions = torch.where(stand, a_stand, a_s1))
- **Entry / exit:** entry on the FIRST stand step; exit on the step the command changes (a stand -> move / turn change hands back to S1 on that step); turn holds (speed 0 with a facing change) stay S1's; the latch is re-derived on reset
- **Stand-net input:** scripts/sn_common.py stand_net_input(obs, stand_estimator, p0, p1, num_prop, mask=1): the stand checkpoint's OWN estimator on the UNMASKED prop obs[:, :num_prop] -> a NEW tensor cat(obs[:, :p0], est, obs[:, p1:]) -> stand_mask_obs (mdp/crab_hex_omni_restance.py) because stand_mask is 1: the current step's last-action block (cols 65-82) set to 0.0 and contact / current-sense proxy block (cols 83-88) set to -0.5, and the same two blocks of each of the 10 history frames (cols 259 + 89 j + 65..88); the harness obs is never written (S1 never sees a masked frame)
- **Forward:** act_inference(stand_net_input(obs, stand_estimator, p0, p1, num_prop, mask=1), hist_encoding=True) -- the actor mean (the std never acts); p0 / p1 / num_prop from the estimator cfg, never hard-coded
- **Reference implementation:** experiments/2026-10-11_stand_network/scripts/sn_stand_net_eval_crab_hex_gait.py (launcher variant stand_net: StandNetMode.__call__, bind_s1 / trained_arm refusals) + scripts/sn_common.py (stand_net_input, route_actions); the video recorder scripts/sn_record_video.py runs the same step (sn_video_core.route_step)
- **Environment (both networks, one process):** the walker's carry block (Observation contract above) with `KRABBY_OMNI_CLOCK_HIDE=1`; in particular `KRABBY_OMNI_STAND_OBS=0`, `KRABBY_OMNI_STAND_HOLD=0`, `KRABBY_OMNI_STAND_PARK=0`, `KRABBY_STD_PARAM=soft`, `KRABBY_OMNI_SPEED_ELLIPSE=0.35:0.35:0.25`, `KRABBY_OMNI_FACING_OBS_CLIP=0.6`; unset (or `''` / `0`): `KRABBY_OMNI_STAND_MASK`, `KRABBY_OMNI_STAND_PROXY`, `KRABBY_RESTANCE` and any `P2R_*` variable.
- **CAVEAT (switch keying):** the eval's LATCHED stand slot keeps reading "turning" after any facing change until a new facing target or a reset (CHARTER 3, 2026-10-13 video finding: on a random 180-s schedule it read TURN on 7 of 10 stands, every stand after the first facing change -- under the evaluated contract S1 would have marched through them). ## Resuming training from a stage head

`KRABBY_OMNI_PHASE=<the next stage's phase>` (the `Preset + overlay` column) + the next stage's overlay (its `overlay_ref`, every key) `... train.py --task <the next stage's task> --resume --checkpoint <policy path>` (tasks by preset: `Isaac-Crab-Hex-Omni-Walk-v0` (1b), `Isaac-Crab-Hex-Omni-Walk-v0` (1a), `Isaac-Crab-Hex-Omni-Teacher-v0` (2a)), as the campaign drivers (`experiments/tools/run_candidates.py`, `checkpoint:` / `reference:` resume kinds) do. Every overlay here also carries the runner-side construction knobs (manifest `construction:`: `KRABBY_ACTION_BOUND_LOSS=0.001`, `KRABBY_ACTION_BOUND_RAMP=0.0001:0.001:500`, `KRABBY_ACTION_BOUND=1.1`, `KRABBY_STD_PARAM=soft`, `KRABBY_INIT_STD=0.8`, `KRABBY_ENTROPY_COEF=0.0025`, `KRABBY_ACTION_RATE_W=0`), except where a stage lists a `construction_delta`; a fork must keep them -- without `KRABBY_STD_PARAM` as trained the checkpoint does not load (strict load, `std` vs `std_raw`). A fork of the current head keeps `KRABBY_OMNI_CLOCK_HIDE=1` and the eps clock weights unless it deliberately restores the clock.

## Maintenance

- `python3 parkour_tasks/parkour_tasks/crab_hex_omni_task/experiments/tools/bundle_policy.py --check` (from `parkour/`; the tool is cwd-independent) -- every stage file present with its manifest sha, no stray checkpoints, README fresh (run by `tests/unit/test_policy_of_record_omni.py`).
- New bake: add/replace the stage entry in `manifest.yaml` (source run, sha256, campaign, overlay_ref, obs_contract, evals), set `current`, `git rm` the replaced stage files (`--sync` never deletes; `--check` flags them as stray checkpoints), run `--sync`, commit.
- New shared asset (e.g. a re-harvested RSI bank): add an `assets:` entry (dir, file, source, sha256, what, used_by), run `--sync`, commit.
- Stand network (`stand_network:`, folder `stand_net/`): `--sync` copies its file from `source` sha-verified, `--check` verifies it like a stage (present, sha, no stray checkpoint). Required keys: `dir`, `file`, `source`, `sha256`, `adopted`, `arm`, `stand_mask`, `walker`, `deployment`; `walker` must name a stage and repeat that stage's sha256, so re-baking the walking head forces a decision on the stand network (it was trained and gated beside that exact walker). Replace it: edit the block, `git rm` the old file, run `--sync`, commit.
- No MDP pins: the omni lineage's stage recipes are overlays on a `KRABBY_OMNI_PHASE` preset (each stage's `phase`) recorded in campaign `candidates.yaml` files, not presets, so there is no `--pin-mdp` / `POLICY_SUMMARY.md` here (the forward policy folder has both).
