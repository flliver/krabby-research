### Deployment contract (as evaluated)

- **Switch:** HARD switch, no blending, no debounce (as before): the stand net acts on the EFFECTIVE stand rows = stand holds OR restore rows (sh_core.effective_stand / route: torch.where(stand_eff, a_stand, clamp(S1, +-1))), the walker (S1) on every other row; both networks run every step. Restore rows are stand-net rows
- **Entry / exit:** entry on the FIRST stand step; on the step the command leaves stand the stand net keeps acting if a restore engages (below) and hands back to S1 when it completes or times out, otherwise S1 acts from that step; turn holds (speed 0 with a facing change) stay S1's; the latch is re-derived on reset; a stand arriving mid-restore merges (the restore ends, the new stand continues from the limiter's state)
- **Stand-net input:** sh_core.stand_net_input(obs, stand_estimator, p0, p1, num_prop, mask=1, h_cmd_limited=h_lim, restoring) = the predecessor's input (experiments/2026-10-11_stand_network/scripts/sn_common.py stand_net_input: the stand checkpoint's OWN estimator on the UNMASKED prop obs[:, :num_prop] -> a NEW tensor cat(obs[:, :p0], est, obs[:, p1:]) -> the A-mask because stand_mask is 1: the current step's last-action block (cols 65-82) = 0.0 and the contact / current-sense proxy block (cols 83-88) = -0.5, and the same two blocks of each of the 10 history frames (cols 259 + 89 j + 65..88)), then, AFTER the estimate and on that new tensor only: column 15 (the hidden clock column, 0 for the walker) = (h_lim - 1.064) / 0.4 on every row (history frames untouched), and on restore rows the current-frame command columns 5, 8, 9, 10 (yaw-rate command, xy command, its norm) = 0. The harness obs is never written (S1 never sees a masked or height-written frame)
- **Forward:** act_inference(stand_net_input(...), hist_encoding=True) -- the actor mean (the std never acts); p0 / p1 / num_prop from the estimator cfg, never hard-coded

## Resuming training from a stage head

`KRABBY_OMNI_PHASE=<the next stage's phase>` (the `Preset + overlay` column) + the next stage's overlay (its `overlay_ref`, every key) `... train.py --task <the next stage's task> --resume --checkpoint <policy path>` (tasks by preset: `Isaac-Crab-Hex-Omni-Walk-v0` (1b), `Isaac-Crab-Hex-Omni-Walk-v0` (1a), `Isaac-Crab-Hex-Omni-Teacher-v0` (2a)), as the campaign drivers (`experiments/tools/run_candidates.py`, `checkpoint:` / `reference:` resume kinds) do. Every overlay here also carries the runner-side construction knobs (manifest `construction:`: `KRABBY_ACTION_BOUND_LOSS=0.001`, `KRABBY_ACTION_BOUND_RAMP=0.0001:0.001:500`, `KRABBY_ACTION_BOUND=1.1`, `KRABBY_STD_PARAM=soft`, `KRABBY_INIT_STD=0.8`, `KRABBY_ENTROPY_COEF=0.0025`, `KRABBY_ACTION_RATE_W=0`), except where a stage lists a `construction_delta`; a fork must keep them -- without `KRABBY_STD_PARAM` as trained the checkpoint does not load (strict load, `std` vs `std_raw`). A fork of the current head keeps `KRABBY_OMNI_CLOCK_HIDE=1` and the eps clock weights unless it deliberately restores the clock.

## Maintenance

- `python3 parkour_tasks/parkour_tasks/crab_hex_omni_task/experiments/tools/bundle_policy.py --check` (from `parkour/`; the tool is cwd-independent) -- every stage file present with its manifest sha, no stray checkpoints, README fresh (run by `tests/unit/test_policy_of_record_omni.py`).
- New bake: add/replace the stage entry in `manifest.yaml` (source run, sha256, campaign, overlay_ref, obs_contract, evals), set `current`, `git rm` the replaced stage files (`--sync` never deletes; `--check` flags them as stray checkpoints), run `--sync`, commit.
- New shared asset (e.g. a re-harvested RSI bank): add an `assets:` entry (dir, file, source, sha256, what, used_by), run `--sync`, commit.
- Stand network (`stand_network:`, folder `stand_net/`): `--sync` copies its file and its `warm_start` ancestor's from `source` sha-verified, `--check` verifies both like a stage (present, sha, no other checkpoint in the folder). Required keys: `dir`, `file`, `source`, `sha256`, `adopted`, `arm`, `stand_mask`, `walker`, `deployment`; `walker` must name a stage and repeat that stage's sha256, so re-baking the walking head forces a decision on the stand network (it was trained and gated beside that exact walker); an optional `warm_start` (`id`, `file`, `source`, `sha256`, `role`) bundles the checkpoint it was warm-started from in the same folder. Replace it: edit the block, record the replaced net under `superseded:` (its commit and file sha), `git rm` the old file unless the new net was warm-started from it and keeps it as `warm_start`, run `--sync`, commit.
- No MDP pins: the omni lineage's stage recipes are overlays on a `KRABBY_OMNI_PHASE` preset (each stage's `phase`) recorded in campaign `candidates.yaml` files, not presets, so there is no `--pin-mdp` / `POLICY_SUMMARY.md` here (the forward policy folder has both).
