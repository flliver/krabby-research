# Crab hexapod — forward-walk policy configuration (parkour / Isaac Lab)

This document describes the **crab hexapod forward-walk task** (`parkour/parkour_tasks/parkour_tasks/crab_hex_forward_task`) policy, scene, and training configuration in **krabby-research**: file layout, observation/action/depth behavior, environment variables, and how to run tests and short training. Design write-ups elsewhere may use different dimensions or pseudocode; **this file matches the code in this repository.**

## Scope

- **Six legs:** Six foot bodies via `.*_Footpad` (`_CRAB_FOOT_BODY_NAMES`, one footpad fixed to each `*_Tibia`); **18** actuated action channels (6 legs × 3: cam-shaft velocity + hip-femur and femur-tibia position; the six `*_Body_Hip_RevoluteJoint` yaw joints are passive, slaved to the cam shaft).
- **PPO / policy:** Teacher and student gym ids; runner `OnPolicyRunnerCrabHex` (resolves `CrabHexActorCriticRMA`, an `ActorCriticRMA` whose exploration std is clamped to [0.05, 2.0] during rollouts); `PPOWithExtractor` for flat-walk / phase-2 teacher training with the mirror-symmetry loss on by default (`KRABBY_SYM_LOSS_COEF`, 0.5; 0 disables); the student runs `DistillationWithExtractor`.
- **Depth:** Student scene uses the shared parkour ray-caster camera pattern, aligned with `parkour_tasks/default_cfg.py` (`CAMERA_CFG`).
- **Policy of record:** `crab_hex_forward_task/policy/` — the shipped head (`3a_student/model_24995.pt`, depth student) and the stage heads it was trained through (`1a_formation` → `2a_elements` → `2b_clearance` → `2c_teacher`), sha-pinned in `policy/manifest.yaml`; see [policy/README.md](../parkour/parkour_tasks/parkour_tasks/crab_hex_forward_task/policy/README.md); [policy/POLICY_SUMMARY.md](../parkour/parkour_tasks/parkour_tasks/crab_hex_forward_task/policy/POLICY_SUMMARY.md) explains what each stage was trained on (active rewards, terrain and knobs per phase, plus the reward and terrain catalogues).
- **Asset:** `assets/crab.usda` — the main plant ("A15+B" geometry), generated by `assets/scripts/generate_crab.py`. The byte-pinned **legacy golden** (2026-08-20 build) is `assets/variants/crab_simple__splay00_axis5p5in.usda`, selected with `KRABBY_PLANT=legacy_golden`; the other variants live beside it under `assets/variants/`. `assets/crab_simple.usda` is the hand-authored Cube model of the 2026-08-09 campaign baseline, kept for reference only (no task loads it). Geometry, provenance, and plant selection: [crab-hexapod-plant.md](crab-hexapod-plant.md). Expert override only: `KRABBY_HEX_USD_PATH` (see the env-var table).

## Observation and action

- **Policy observation:** single term `extreme_parkour_observations`, func `CrabHexParkourObservations` (`mdp/observations.py`, subclass of `ExtremeParkourObservations`) in `CrabHexTeacherObservationsCfg`; `CrabHexStudentObservationsCfg` adds the `depth_camera` (58×87, buffer 2) and `delta_yaw_ok` groups. Proprio block (89 dims on the 24-DOF plant): ang-vel × 0.25 (3), roll/pitch (2), steering [0, delta_yaw, delta_next_yaw] (3), command [0, 0, vx] (3), tile flags [on-obstacle, on-flat] (2), body-frame lin-vel xy × 2 (2), gait-clock sin/cos (2), joint_pos − default (24; cam-shaft channels wrapped to ±π), joint_vel × 0.05 (24), last clipped action (18), 6 current-sense stance proxies (−0.5 idle … ~+1; there are no foot-contact bits). Then the height scan (108 points: the crab scanner is a 2.4 × 3.4 m grid at 0.3 m, 9 × 12 rays, `_apply_crab_height_scanner`), 9 priv-explicit, 53 priv-latent (mass 1 + CoM 3 + friction 1 + 24 stiffness + 24 damping ratios) and `history_length = 10` copies of the proprio block: 89 × 11 + 108 + 9 + 53 = **1149** for the `policy` group — the `obs_dim_actual` the gait harness records in every eval's `run_meta.json` since the clock dims were added (2026-08-22; pre-clock heads recorded 1127, era-A heads 1151). The network slices with `CrabHexParkourRslRlBaseCfg` (`num_prop=75`, `num_scan=132`, `num_priv_explicit=9`, `num_priv_latent=41`, `num_hist=10`), which predates the 24-DOF plant and the clock dims — train and play share the slicing so it is self-consistent, but the 'scan' slice is not the height scan (the harness records an `obs_dim_warning`).
- **Steering channels on flat tiles:** zero unless `KRABBY_HEADING` is set, in which case they carry the heading-command error `wrap_to_pi(heading_target - heading_w)` (presence-based — `KRABBY_HEADING=0:0` still switches the semantics). Heads trained from phase 2b on (presets 2b/2c/3a/3b and legacy_golden_2b..2e) expect the heading channels live; export the same `KRABBY_HEADING` band (or the `KRABBY_PHASE`) when playing or evaluating them.
- **Actions:** `CrabHexDelayedJointPositionActionCfg` (`mdp/parkour_actions.py`) on `.*_Body_CamShaft_RevoluteJoint` (velocity target, scale π rad/s, raw clip ±1 at every stage — lower bound adjustable with `KRABBY_CAM_CLIP_LO`), `.*_Hip_Femur_RevoluteJoint` and `.*_Femur_Tibia_RevoluteJoint` (position targets) → **18** dims. `.*_Body_Hip_RevoluteJoint` is passive (its target is computed from the cam-shaft angle). Position scale / raw clip: 0.25 (`KRABBY_ACTION_SCALE`) / ±4.8 for Flat-Walk-v0, the phase-2 modes 2a/2b/2c and the phase-3 student (`_apply_crab_hex_full_actions`); 0.24 / ±1 for the legacy bridge/2b1/2b2 modes. The flat-walk, phase-2 (2a/2b/2c), bridge/2b1/2b2 and student runners clip raw actions to ±1 first (`clip_actions = 1.0`); the legacy `full`/`full1`/`full2` teacher modes leave it unset. Hip/knee targets then pass through the linear-actuator layer (rod-window clamp, rod-speed slew, hip→knee coupling); the cam speed command is acceleration-slewed.
- **Critic / privileged:** Inherited parkour teacher pattern (same family as Go2 teacher).

## Depth camera

- **Student:** `CrabHexStudentSceneCfg` sets `depth_camera = CAMERA_CFG.replace(prim_path="{ENV_REGEX_NS}/Robot/chassis/body", offset=CAMERA_CFG.offset.replace(pos=(0.37, 0.0, 0.10)))` — a ray-caster camera on the chassis body, 0.37 m forward / 0.10 m up (placeholder pending the real mount).
- **`CAMERA_CFG`:** `RayCasterCameraCfg`, `distance_to_camera`, pattern **height=60, width=106**, orientation shared with the parkour stack (`parkour_tasks/default_cfg.py`); the position offset is overridden from the Go2 (0.33, 0.0, 0.08). The student obs term `depth_cam` resizes frames to (58, 87) and stacks 2.
- **USD:** no camera prim — the plant `assets/crab.usda` carries only the articulation (`assets/crab_hex.usda` is the legacy Blender/HAL model and is not loaded by any training task).

## Rewards (hex naming)

- Base / collision bodies: `body`, `.*_Hip`, `.*_Femur` (`reward_collision` sensor_cfg).
- Feet / edge / stumble / air-time: `.*_Footpad` (contact sensor `contact_forces` on `{ENV_REGEX_NS}/Robot/.*`; leg order FL, FR, ML, MR, RL, RR = `_CRAB_FOOT_BODY_NAMES`).
- Hip posture: `.*_Body_Hip_RevoluteJoint` (`reward_hip_pos`, passive yaw joint); position-deviation terms are restricted to `.*_Hip_Femur_RevoluteJoint` / `.*_Femur_Tibia_RevoluteJoint` (`_CRAB_POSITION_ACTUATED_JOINT_NAMES`).

## Gait tuning (where to look)

- Commands: `CommandsCfg` / `base_velocity`.
- Rewards: `CrabHexRewardsCfg`.
- Terrain / curriculum: `apply_flat_walk_knobs` in `crab_hex_env_cfg.py` (`KRABBY_FLAT_TERRAIN_MODE/FLAT_FRAC/DIFF/GEOM/CURRICULUM`, `KRABBY_TERRAIN_PROMOTE`, `KRABBY_PHASEOUT`), values per phase in `crab_hex_phases.py`; only the legacy `bridge/2b1/2b2/full*` teacher modes keep their own terrain helpers.

## Isaac Sim 5.x / rsl_rl notes

- **`PPOWithExtractor`:** Standalone trainer using `RolloutStorage` with `TensorDict` keys `policy` and `critic` (not a subclass of stock `rsl_rl.PPO`).
- **`OnPolicyRunnerWithExtractor`:** `add_git_repo_to_log` → `git_status_repos`; `store_code_state` optional with one-time warning; `multi_gpu_cfg` from `cfg["multi_gpu"]`; `process_env_step` takes post-step `TensorDict`.
- Extra algorithm keys (e.g. `share_cnn_encoders`) may be filtered with a warning.
